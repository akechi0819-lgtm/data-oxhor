# 线上看板费用与ROI

## 当前费用采集与计算入口（2026-11-03）

整批广告来源的本地采集与候选构建入口为 `data_acquisition.jobs.prepare_full_daily`。它按工作区 `.private/full-daily-sources.json` 和已观测来源合同采集配置范围内的小红书、巨量、腾讯广告账户账本，并校验腾讯竞价／品牌明细范围；SEM需显式传入 `--sem-auto` 使用已保存的钉钉专用状态，或传入 `--sem-receipt`。SEM缺少或过期登录态会阻断，不弹登录窗口。

```sh
python3 -m data_acquisition.jobs.prepare_full_daily \
  --workspace customers/shadow_bi_daily \
  --batch-dir '.local/audits/full-daily-<本次唯一目录>' \
  --source-contracts '<已验收来源合同目录>' \
  --xhs-scope '<已验收小红书范围回执>' \
  --sem-auto
```

默认 `--prepare` 模式会生成隔离的本地费用候选，不更新正式费用清单、看板指针或通知。`--publish` 才会进入 business-first 流程，依次完成业务看板、日推和费用更新的既有门禁；此命令本身不会创建或启用日程。`Input/AdvertisingCosts/sources.json` 仍用于来源映射及普通看板构建；用户提供的费用原表继续可登记处理。连接器覆盖、每日实际运行和发布状态应分别核实，不能从有入口推断已排程或已发布。

## 来源与SQL

- 费用可以由用户提供的原表登记到客户工作区 `Input/AdvertisingCosts/sources.json`，再由 `shadow_bi.library`（内部调用 `management.calculation.calculate`）读取；整批采集则由 `prepare_full_daily` 生成当前run的费用manifest供本地候选或 business-first 发布流程使用。`sources.json` 中的账户／工作表映射同时用于自动候选解析。连接器只采集已配置并通过来源合同与完整性核验的范围。
- 2026-10-12手工输入批次中，语培为3份小红书账户日报及3份已确认业务组的巨量日报，留学为网络期间总表“总推广费用”。这是当时的文件清单，不代表后续批次必须继续使用相同人工材料或来源范围。
- 当前批次原件放在 `Input/AdvertisingCosts/files/<source_id>.<suffix>`，清单使用相对路径并登记 SHA-256。`advertising_sources.py`只读解析已登记文件，不修改原始输入。合计行仅对账；同一物理文件或相同文件摘要重复声明会阻断。费用保留来源行、原周期、平台、业务线与业务组，真实0和缺失分别保留。
- `advertising_costs.py`复用现有线上团队资格和当前共同事实，不把人员、主被动、团队或年级口径重新写成另一套SQL。日期、业务线、业务组、平台先成为唯一业务汇总输入；不包含客户姓名或客户ID。
- 匹配规则位于 `dashboard_product/management/sql/advertising_rollup.sql`。业务量与费用各自先汇总，再按业务线、业务组、平台关联；平台、业务组和业务线汇总使用同一叶级结果。无业务量但有费用的平台仍显示，不把花费重复关联到每个原子渠道。
- 宿主将当前事实与费用输入编码为带类型的VALUES，再通过Data Platform只读入口执行SQL；不直接连接客户DuckDB，不在SQL中打开CSV或Excel。生成SQL与查询回执保留在每个管理批次，`advertising_sources.json`和`advertising_result.json`是私有校验材料，不公开发布。
- `shadow_bi.library`（内部调用 `management.calculation.calculate`）同批生成线上费用结果；未声明费用清单是合法的“未提供费用”状态，有清单时文件、结构和哈希错误不能静默忽略。新增费用不改通知、总盘或其他页面的业务完成。

## 指标与时间

ROI = 费用共同覆盖期间毛签 / 同期费用；单条工单成本 = 同期费用 / 同期工单。业务组及业务线使用各自汇总金额计算，不平均下级比率。两项均不是利润或客户批次归因。平台ROI不能用子渠道ROI简单平均。

日报每个费用来源必须覆盖所选期间每一天且金额有效，才能视为期间完整；完整性作为来源审计信息保留。比率另取已配置费用流共同、连续覆盖的日期窗口；各平台独立计算，业务组和业务线取参与来源的共同截止。无费用接入的平台不阻断日期窗口，仍不补0。没有费用不补0；确认的零费用保持0，零花费ROI不计算，零工单成本不计算。费用不按工单比例、毛签比例或原子渠道数量分摊。

期间总表仅在其覆盖区间完整落入所选期间时计入已提供费用。只选择部分区间时不能截取期间金额；期间费用不平均分给每天，也不外推到其他月份、季度或全年。本次留学手工表为累计期间表和当月期间表，9月按相同原始渠道以累计金额减当月金额形成差额；两份输入不直接重复相加，差额及来源行保留在私有校验材料中。

每日图按业务线分别展示“已提供花费”柱状和原工单量折线，元/单双轴分开。无日费用的日期不画0柱。日粒度日报可展示每日花费；期间总表不拆分到日，留学图保留工单、毛签折线，每日费用保持未提供；期间摘要显示期间总表费用。
