## 费用录入与来源

日常费用按日期、业务组和平台整理为 CSV、XLSX 或 JSON，通过 `ops ingest-cost` 独立录入。列名为日期、业务组、金额，也支持 `date`、`business_group`、`amount`。平台参数为 `xhs`、`douyin`、`tencent` 或 `sem`，SEM 每行还须声明具体平台。命令及零消费声明示例见[本地运维手册](operator-runbook.md)。

录入会在隔离候选核对后发布费用视图，并沿用当前业务仓和通知预览。录入前核对同组、同平台、同日已有费用和期间账单，确保来源覆盖范围准确。原始行保留日期、来源和金额状态，空金额保持缺失。已明确为零的费用可在文件填 0 或使用 `--confirm-zero` 声明。腾讯在 ROI 看板的计算使用已确认的缺日零费用规则。

需要核验原生账户流水时，可按需运行 `ops fetch-cost-optional`，生成本地来源证据。日常业务更新由 `ops run business` 执行，费用另行处理。账号及数据来源的历史替代关系可追查工作区 `Input/AdvertisingCosts/` 和各批回执。

## 费用与平台口径

留学投流工单按三级渠道归属，签约按渠道明细归属。三平台范围使用 `management/platforms.py` 的已确认名单。语培按已有原始渠道规则分类。范围外的平台保留相应分类，费用不按工单或签约金额分摊给细分渠道。

ROI 看板的月度、季度和财年使用整个选定期间的工单与产出。日费按实际已录金额加总，期间费用仅在整个原周期落入所选期间时计入，不分摊为日费。平台合计先合并金额和工单，再计算 ROI 和单条成本。SEM 叶表按已确认的业务线、业务组及平台读取，空白金额在源明细中保留缺失。平台数据和账户来源的历史接入记录见 [SEM 及平台流水接入记录](archive/shadow-bi-p55-project-sem-20261027.md)。

`business.scoped_advertising_rollup` 仍保留费用来源共同覆盖窗口及其计算字段，用于来源覆盖与既有报表；ROI 看板按本页现行的完整选定期间计算。两套查询用途不同，核对线上 ROI 看板时使用 `sql_warehouse/roi_dashboard.py` 定义的数据集。
