# Business Data MCP 最小施工计划

日期：2026年11月5日。基础数仓和业务 MCP 公网查询已验收。WorkBuddy 已实测通过正确取数、关键数字独立核对、追问口径与版本、1,302 行完整 CSV、个人口径跨会话复用和权限撤销。原因推理质量由宿主模型与轻量 Skill 引导，不作为 MCP 接入验收门槛；本轮不按模型定制规则，也不要求固定分析流程或证据表。此状态不表示模型推理问题已解决。用户决定本轮不安装豆包工作，因此未测试且不在本轮范围。

目标是让现有看板各团队主管，用自己的 Agent 从每天更新的云端数仓按需取数，回答自然语言提出的真实业务问题。验收关注取数正确、关键数字可独立核对、追问时口径与版本一致、完整 CSV、个人口径复用和权限撤销。小结果直接展示表格，需要文件时只导出本次查询结果的 CSV。

需求以 PRD v2.1 和本轮用户澄清为依据；发生冲突时以本轮澄清为准。PPT、HTML 报告制作不列入验收，没有定时巡检和主动提醒。

## 云端与本机分工

| 位置 | 职责与保存内容 |
|---|---|
| 云端 | 现有数仓和更新链；只读查询；数据版本与来源；本次结果的短期读取和 CSV 交付 |
| 使用者自己的 Agent | 理解问题、必要追问、选择数据、生成 SQL、按用户需要继续分析 |
| 本机 Skill 与业务记忆 | 简短的取数用法、必要公司口径参考、使用者自己的分类和业务经验 |
| 本机用户文件 | 用户主动保存的本次结果 CSV；不自动下载全量底表或保留每次查询副本 |

后续取数继续访问云端当前已发布数据。需要在同一次问答中保持一致时固定具体版本；源版本不可用则明确说明。结果分页和 CSV 来自同一次已执行查询，不因日更而改变。

本机没有数仓副本、每日数据同步、自动归档目录或离线库。仅按需取得相关记录或汇总，不把整个底表送入模型或下载到主管电脑。用户主动保存的 CSV 是一次取数结果，标明查询范围和数据日期，不承担持续更新的数仓职责。

## Skill 和业务记忆保持轻量

提供一份简短 Skill，说明怎样调用 MCP、怎样查看可用字段、怎样取得完整 CSV，以及怎样引用本机已有业务记忆。不规定调查步骤、拆解维度、异常判断方法或报告结构，不要求用户必须从看板发现异常后才能使用。

公司参考只附实际必要且已有确认的定义，可引用现有 Bridge 或说明；不重新建设语义目录或指标知识库。公司 Bridge 和个人材料均可放在本机，不部署服务端 Bridge 托管，不强制文件格式或自动同步。

看板分类、主管自定义的学校分类和业务周期都可作为查询参考。Agent 按本次问题选用，有影响结果的歧义再追问。主管可以提供口述背景或本地文件；回答时区分这些材料与数仓证据即可。

## MCP 的最小能力

复用现有受控查询和来源校验，使用官方 SDK 提供远程 MCP，不另建服务端分析模型。服务按实际路径提供以下能力，具体工具数可合并：

- 了解四张底表及查看实际字段和必要关联说明。
- 接收 Agent 生成的只读 SQL，按问题筛选、关联和汇总。
- 返回简短表格及数据范围；较大结果支持继续读取。
- 将本次完整结果交付为 CSV，只保留这一种用户导出格式。

每人独立 Key，在客户端配置一次，可单独撤销。查询、后续结果读取和新的 CSV 获取都检查授权；不增加复杂权限后台。

沿用只读限制，并实现可实际终止的查询超时及适当资源限制，保护同机 BI。数值限额通过代表性查询测试决定，不把未经验证的阈值写成业务范围。完成查询后仅为分页和 CSV 获取短期保存结果，不长期保留整库或所有历史查询结果；源库只在实际查询读取期间保护。

CSV 完整交付先验证客户端已有能力。确需额外下载路径时，再采用与该 Key 撤销状态关联的短期下载授权。不得在未测试前同时建设多套文件通道或第二种导出格式。

## 施工顺序

### 第一阶段 跑通一个真实取数问题

使用已交接的四张逻辑底表和双 Snapshot 入口。复用现有代码搭起最小服务骨架，在 WorkBuddy 用真实业务问题核验取数、关键数字独立复核、追问口径与版本，并交付完整 CSV。原因推理不设 MCP 接入门槛。合成数据仅补充长ID、前导零、中文、空值和超过预览规模等交付检查，不另建一次性过渡服务。

交付：四表接入清单、真实业务问题取数样例、关键数字独立核对、完整CSV核对结果、实际需改动的代码范围。豆包工作未测试且不在本轮范围。

### 第二阶段 完成访问和结果交付

在同一服务骨架上完成四表查询、Key管理、结果读取、CSV交付、来源版本和必要资源控制。根据第一阶段查到的具体缺口扩展已有接口，不预先修改基础数仓或日更链。

交付：可复用服务、轻量Skill、本机业务记忆用法、WorkBuddy 脱敏配置及相关检查结果。没有必要的语义材料不加入分发包，个人业务记忆由主管自行积累。

### 第三阶段 已授权客户端验证并分发

在 WorkBuddy 中用真实业务问题验证正确取数和关键数字独立核对；追问时检查口径与版本保持一致，并验证完整 CSV、个人口径复用和权限撤销。原因推理由宿主模型与轻量 Skill 引导，不要求固定分析流程或证据表。豆包工作用户决定不安装，本轮不测试。

同时验证独立Key撤销、结果隔离、只读、实际超时终止和数据更新后的版本说明。报告制作不列验收，按PRD中的仍适用条目记录通过、失败或未测试；真实业务问题用于核验取数和数字，原因推理质量不作为MCP接入验收门槛。豆包工作未测试且不在范围。

交付：WorkBuddy 接入说明、CSV样例、取数与关键数字核对证据、Key管理和撤回说明。模型原因推理表现留在历史审计中，不据本轮接入验收表述为已解决。
