# Data OXHor 使用说明

## 市场日常工作入口

临时查询、细分下钻、导表和生成小程序，打开项目内 `market_workspace/`。Agent 按该目录的 `AGENTS.md` 调用 `./oxhor` 受控查询，源数据仍为原 bi_operations 工作区。程序放 Programs，临时脚本放 Scratch，正式成果放 Reports，查询证据放 Evidence；清理前只选择不再需要的任务子目录。详细操作见 [市场工作区说明](../market_workspace/README.md)。导入新数据、改变正式口径或维护看板/监控时，转对应模块。

Data OXHor 是由多个可独立选择的模块组成的运营数据中台。使用时先根据任务选择一个模块 Agent，再在对应客户工作区中运行。项目没有负责所有场景的总 Agent；宿主负责会话、模型和模块之间的协作。

常用模块包括：工作区初始化、自由分析、看板发布和预留的日常监控。每个模块的启动说明见根目录 [`agents/`](../agents/README.md)。

## 自由分析

Bridge 对齐完成后，直接提出问题：

```text
查一下本月各校区净现金，并和上月比较。
为什么 A 校区净现金下降？请按来源和时间拆解。
看一下工单渠道和现金记录能匹配多少。
找出负向现金最多的校区，并列出需要进一步确认的原因。
```

Agent 会先检查当前工作区是否有可用 Snapshot 和兼容 Bridge，再基于当前数据重新查询。历史案例只帮助复用分析方法，不能直接提供旧数字。

回答会说明时间范围、指标口径、数据来源和限制。负向现金不自动等同于退款；日期范围重叠也不自动证明记录重复。

## 生成交付物

在分析结论明确后，可以继续说：

```text
把刚才的分析做成一份 4 页 PPT。
导出一张可以继续编辑的明细表。
做一张按校区比较的图表，并附上结论和数据限制。
```

Agent 会检查文件是否能打开、内容是否为空，以及关键数字是否来自本次查询。模板、图片、旁白或复杂动画请明确说明，这类任务会走更完整的交付流程。

## 第一次使用

如果还没有客户工作区，可以说：

```text
帮我首次部署 Data OXHor。
检查运行环境，初始化我的客户工作区。
```

Agent 会依次引导你检查运行环境、选择业务端口、创建工作区、放入数据、发布当前 Snapshot，并进入 Bridge 对齐。常见业务端口包括高中、初中、市场、运营、教学。

缺少业务端口、数据文件、来源名称或替换确认时，Agent 会提问，不会猜测。

## 导入和更新数据

可以说：

```text
导入这几张流水表，帮我建立分析环境。
更新本月现金表，使用新的数据快照。
```

多张表最好补充用途，例如“这是现金明细，这是工单记录”。更新会发布新的显式 Snapshot，不会直接覆盖已发布数据；来源文件由你自行归档。

## 建立业务口径

首次导入后可以说：

```text
开始建立 Bridge。
```

Agent 会提出字段和业务口径候选，然后逐项向你确认：

```text
这个字段就是校区。
净现金按收入减支出计算，负数保留，不要自动当成退款。
付款人和学员在这里按同一个客户识别。
```

没有确认的关键口径不会进入正式分析。你也可以说“这个不确定”，Agent 会保留问题并请求更多证据。

## 保存案例和复用方法

一次分析确认完成、以后可能重复使用时，可以说：

```text
这个分析已经确认，请保存为以后可复用的案例。
```

Agent 会先保存为待确认案例。你检查后再说“确认保存这个案例”。案例保存问题、方法、证据和限制，不保存永久不变的当前数字；下一次仍会查询当前 Snapshot。

需要复用以前的方法时，可以说：

```text
找一下以前有没有类似的净现金分析案例。
```

同类问题反复出现时，可以说“检查这些案例是否值得提炼成 Skill”。系统只返回待审核候选，不会自动修改或发布 Skill、模板、Pack 或 Bridge。

## 内测反馈

可以说：

```text
开始一轮内测。
导出这轮内测的脱敏反馈。
```

默认反馈不包含工作簿、数据库或完整运行目录。只有你明确授权的证据才会被附加。

## 看板发布

固定看板不走自由分析。刷新、渲染和发布使用看板发布 Agent：一次读取当前 Snapshot，生成全量 `artifact.json`，再渲染四分册 HTML 并上传。钉钉人员进度是另一次发送，默认先 dry-run。

```text
刷新本月看板并发布四分册。
先预览钉钉人员进度，不要群发。
```

密钥和 webhook 不在对话里填写。公开入口是 `http://dashboard.apinova.cn`，业务页需要账号。详细步骤见 [`dashboard_product/DEPLOYMENT.md`](../dashboard_product/DEPLOYMENT.md)。

## 常用表达

| 目标 | 示例 |
|---|---|
| 日常分析 | `净现金环比`、`同比`、`异常诊断`、`下钻原因` |
| 看板发布 | `刷新看板`、`发布四分册`、`预览钉钉进度` |
| 文件交付 | `做成 PPT`、`导出表格`、`生成图表` |
| 数据更新 | `导入数据`、`更新本月数据`、`发布新快照` |
| 口径对齐 | `建立 Bridge`、`对齐字段`、`确认这个字段含义` |
| 数据诊断 | `检查重复`、`看是否全量刷新`、`诊断数据重叠` |
| 案例复用 | `找类似案例`、`记录这个 Case`、`提炼成 Skill 候选` |

## 使用边界

- 关键字段和业务口径需要你确认，Agent 不会把猜测当成正式事实；
- 当前金额、数量和状态必须基于当前数据重新查询；
- Casebook 是方法参考，不是当前数据源；
- Agent 不会自动上传客户文件，也不会默认读取整个运行目录；
- 负向现金不等于退款，具体原因需要结合业务确认；
- 如果工作区还没有完成 Bridge 对齐，Agent 会先带你完成对齐，而不是直接给出正式业务结论。
