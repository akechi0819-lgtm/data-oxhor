# Agent 使用说明

这是一套通过自然语言使用的企业数据分析 Agent。你不需要记住 Python、DuckDB 或 SQL 命令，直接告诉 Agent 你想完成什么即可。首次使用时，Agent 关注的是你要分析的业务端口，而不是公司名称。

## 第一次使用

可以直接说：

```text
帮我首次部署这个 Agent。
```

或：

```text
检查运行环境，初始化我的客户工作区。
```

Agent 会依次引导你：

1. 检查运行环境；
2. 创建客户工作区；
3. 引导你放入基础流水表；
4. 读取并发布当前数据快照；
5. 进入业务 Bridge 对齐。

如果缺少业务端口、数据文件或来源名称，Agent 会先向你提问，不会猜测。常见业务端口包括：高中、初中、市场、运营、教学。

## 导入数据

把文件放到 Agent 可以访问的位置后，可以说：

```text
导入这几张流水表，帮我建立分析环境。
```

对于多张表，最好补充它们的用途：

```text
这张是现金明细，这张是工单记录，这张是客户基础表。
```

更新月份时可以说：

```text
更新本月现金表，使用新的数据快照。
```

系统会保留当前数据的一致性，不会直接覆盖已经发布的快照。来源文件本身仍由你负责归档。

## 建立业务口径

首次导入后说：

```text
开始建立 Bridge。
```

Agent 会根据表结构提出字段和业务口径候选，然后逐项向你确认。常见确认方式包括：

```text
这个字段就是校区。
```

```text
净现金按收入减支出计算，负数保留，不要自动当成退款。
```

```text
付款人和学员在这里按同一个客户识别。
```

确认完成后，可以说：

```text
这些映射确认无误，完成 Bridge。
```

没有确认的关键口径不会进入正式分析。你也可以说“这个不确定”，Agent 会保留问题并继续请求证据或确认。

## 日常分析

Bridge 完成后，直接提出业务问题即可：

```text
查一下本月各校区净现金，并和上月比较。
```

```text
为什么 A 校区净现金下降？请按来源和时间拆解。
```

```text
看一下工单渠道和现金记录能匹配多少。
```

```text
找出负向现金最多的校区，并列出需要进一步确认的原因。
```

Agent 会使用当前数据重新查询。历史案例只能帮助它复用分析方法，不能直接拿历史数字回答当前问题。

## 生成文件

在分析结论明确后，可以继续说：

```text
把刚才的分析做成一份 4 页 PPT。
```

```text
导出一张可以继续编辑的明细表。
```

```text
做一张按校区比较的图表，并附上结论和数据限制。
```

文件生成后，Agent 会检查文件是否能打开、数字是否来自本次查询。若需要模板、图片、旁白或复杂动画，请明确说明；这类任务会走更完整的交付流程。

## 记录 Case 与沉淀方法

当一次分析已经被你确认，并且以后可能重复使用时，可以说：

```text
这个分析已经确认，请保存为以后可复用的案例。
```

Agent 会先保存为待确认案例。你检查无误后再说：

```text
确认保存这个案例。
```

案例保存的是问题、方法、证据和限制，不是永久不变的数字。下一次使用时仍会重新查询当前数据。

需要复用以前的方法时，可以说：

```text
找一下以前有没有类似的净现金分析案例。
```

命中案例后，Agent 只会参考其中的问题结构、查询方法和限制，仍会基于当前 Snapshot 重新查询，不会直接复用旧数字。

当同类问题已经反复出现时，可以说：

```text
检查这些案例是否值得提炼成一个 Skill。
```

或：

```text
把这类重复分析整理成 Skill 或模板候选，先给我审核。
```

系统只会返回待审核的 Skill/模板草案，不会自动创建、修改或发布 Skill。是否沉淀为项目 Skill、行业 Pack、业务 Bridge，仍由你确认。

## 内测反馈

可以说：

```text
开始一轮内测。
```

或：

```text
导出这轮内测的脱敏反馈。
```

默认反馈不包含工作簿、数据库或完整运行目录。只有你明确授权的证据才会被附加。

## 常用关键词

| 你想做什么 | 可以说的关键词或表达 |
|---|---|
| 首次安装和初始化 | `首次部署`、`帮我装好`、`初始化工作区` |
| 放入基础数据 | `导入数据`、`导入流水表`、`更新本月数据` |
| 建立业务口径 | `建立 Bridge`、`对齐字段`、`确认这个字段含义` |
| 检查数据问题 | `检查重复`、`看是否全量刷新`、`诊断数据重叠` |
| 日常分析 | `净现金环比`、`同比`、`异常诊断`、`下钻原因` |
| 文件交付 | `做成 PPT`、`导出表格`、`生成图表` |
| 记录 Case | `记录这个 Case`、`保存为案例`、`这个分析以后复用` |
| 确认 Case | `确认保存这个案例`、`这个案例可以复用`、`把候选转为正式案例` |
| 检索案例 | `找类似案例`、`以前有没有做过这个分析`、`复用之前的方法` |
| 提炼方法 | `检查重复问题`、`提炼成 Skill`、`整理成 Skill/模板候选` |
| 内测和反馈 | `开始内测`、`记录评价`、`导出脱敏反馈` |

## 使用边界

- 关键字段和业务口径需要你确认，Agent 不会把猜测当成正式事实；
- 当前金额、数量和状态必须基于当前数据重新查询；
- Casebook 是方法参考，不是当前数据源；
- Agent 不会自动上传客户文件，也不会默认读取整个运行目录；
- 负向现金不等于退款，具体原因需要结合业务确认；
- 如果数据还没有完成 Bridge 对齐，Agent 会先带你完成对齐，而不是直接给出正式业务结论。

## 一轮标准对话示例

```text
用户：帮我首次部署这个 Agent。
Agent：我先检查运行环境。请告诉我你要分析哪个业务端口，例如高中、初中、市场、运营或教学，并提供对应的数据表。
用户：我要分析高中业务，现金表和工单表已经放好了。
Agent：数据已发布为当前快照。现在开始对齐 Bridge。这个字段是否代表校区？
用户：是。净现金按收入减支出，负数保留。
Agent：Bridge 已完成。你现在可以直接提问。
用户：查本月各校区净现金环比，并做成 PPT。
Agent：我会基于当前快照查询、生成分析，并在导出前检查文件和数字回查。
```
