# 主管接入业务数据 MCP

管理员为每名主管发行独立 Key。服务器地址为 `https://dashboard.apinova.cn/business-mcp/mcp`，传输为 Streamable HTTP。任选客户端使用自己的 Key；本机可只保留客户端连接配置、Skill 和个人口径笔记。

## WorkBuddy

在连接器的自定义 MCP 设置中添加以下条目。如已有其他连接器，将 `business-data` 条目合并到现有 `mcpServers`。一次性替换占位符，保存并在新会话查看是否能发现业务口径、看板结果、明细查询和 CSV 导出工具。可选装同目录的 `business-data-query` 文件夹作为本机 Skill。WorkBuddy 已实测通过正确取数、关键数字独立核对、追问口径与版本、1,302 行完整 CSV、个人口径跨会话复用和权限撤销。原因推理质量由宿主模型与轻量 Skill 引导，不作为 MCP 接入验收门槛；不按模型定制规则，也不要求固定分析流程或证据表。本轮不表示模型推理问题已解决。首次写入配置后需重新启动 WorkBuddy，并在自定义 MCP 管理中确认信任。验收客户端为 macOS 上 WorkBuddy 5.9.4。

```json
{
  "mcpServers": {
    "business-data": {
      "type": "streamableHttp",
      "url": "https://dashboard.apinova.cn/business-mcp/mcp",
      "headers": {"Authorization": "Bearer <本人 Key>"}
    }
  }
}
```

可先问“按月列出留学签约合同数和签约金额”，接着问“每个月有几份合同能按资源 ID 匹配到资源登记？把完整结果给我 CSV”。保留合同但没有匹配到资源的月份和记录。个人口径可以写在自己的业务笔记中，下次提问指明文件，例如“按我笔记中的秋招周期开这张表”。[WorkBuddy 连接器说明](https://open.workbuddy.cn/docs/connector)

## 豆包工作

用户决定本轮不安装豆包工作。该客户端未测试，不在本轮验收范围。

## 管理员

在部署服务器上使用 `business-data-mcp-keys list` 查看标签、Key ID 和状态。`issue` 只返回一次明文，输出重定向到仅管理员可读的交付文件，再经内部安全渠道交给对应使用者。

```sh
umask 077
business-data-mcp-keys issue --label '主管标识' > /root/主管接入.json
business-data-mcp-keys list
business-data-mcp-keys revoke <key_id>
```

更换 Key 时先发行新 Key，替换客户端配置，验证新连接后撤销旧 Key。如需立即中止访问，直接撤销旧 Key。撤销对下一次查询、分页和 CSV 获取生效；已主动保存到本机的文件由主管管理。服务端结果可读取 24 小时。运行单元、容量和回收见[部署说明](../deploy/README.md)。
