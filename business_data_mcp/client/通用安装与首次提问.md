# 安装业务数据 MCP，开始第一次业务调查

你会收到这个教学包和一份个人 Key 文件。请为当前代理安装连接，工具可用后主动执行下方业务题。个人文件 JSON 代码块中的 token 是访问凭据。

## 接入

通过当前客户端支持的远程 MCP 设置添加 business-data 连接。地址为 `https://dashboard.apinova.cn/business-mcp/mcp`，传输协议为 Streamable HTTP。若使用自定义请求头，设置 `Authorization: Bearer <token>`，将占位符替换成个人文件中的 token。若使用 Bearer Token 专用输入框，只填 token 本身。凭据存入客户端凭据设置或用户私有配置，保留其他连接，回复中省略密钥。

连接后即可从服务端读取公司口径。需要操作示例时可加载包内 business-data-query/SKILL.md。

## 首次连接与信任

保存配置后，从当前客户端的 business-data 连接器调用 `describe_data`。如果客户端弹出首次信任提示，或工具尚未出现，请检查这个连接的状态。需要本人操作时，告诉同事在他们当前使用的客户端先打开哪个页面、找到哪个连接、点哪个按钮。按实际界面的名称指路；看不到入口时，请同事提供连接器页面的截图，并提醒遮住凭据。

例如，WorkBuddy 5.9.4 的路径是「专家·技能·连接器 → 连接器 → 自定义连接器 → business-data → 信任」。其他客户端以各自界面为准。请等同事完成确认，再通过客户端连接器调用 `describe_data`，取得可用表、版本和数据截至日；终端直连服务只能验证网络和凭据。连接器可用后，直接继续下方调查，同事无需重新提问。

如果客户端提示重启或新开会话，告诉同事具体操作。若新会话无法延续任务，请留下可直接复制的业务题。若客户端缺少远程 MCP 或 Bearer 认证能力，如实说明停在哪一步。

## 安装成功后直接执行

我负责高校渠道，最近感觉有些学校的校园代理贡献下滑得比较厉害。请用真实业务数据看一下，这个感觉成立吗？挑一所你觉得最值得关注的学校，查查变化主要出现在哪个年级、哪段时间。是资源少了、后续转化变了，还是渠道合作或人员交接方面有值得核实的线索？你自由决定怎么查。最后告诉我，业务会上可以讲什么，下一步该找谁核实什么。

先用 describe_business_context 查看适用口径，从 describe_data 取得正式版本及看板结果目录。导出看板指标用 read_dashboard_data，按看板选择期间、组织和统计范围，使用同一 result_id 导出 CSV。调查需要额外明细时使用 query_data，说明采用的指标、渠道范围、可比期间和数据截至日。给出数字依据，分清已经查实的变化和待核实的解释。完成后向本人反馈安装状态和这次调查结果。
