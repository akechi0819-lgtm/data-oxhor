# 新媒体双周报

用于这个项目的新媒体周报。先读市场工作区 `AGENTS.md`，再读 [数据来源与口径](references/sources.md)。本 Skill 沉淀流程，不保存当期经营事实；每次重查当前数据和用户修改后的报告。用户的当期要求优先。

## 开始

默认按「各项目套图 → 图文双周报 → 按需 PPT」交付。第一阶段按[项目套图口径](references/report-contract.md)和[来源导航](references/source-map.md)核算各项目线上产出，逐项目交付图片与正式配文。本期已有确认版就用该版及其证据。套图确认后才写周报；按用户授权填写钉钉草稿，周报确认后才做所需 PPT。修改现有草稿时保留用户手改内容。每期先执行[核算与交付检查](references/交付检查.md)，不直接复用上期数字、承诺或截图。

1. 明确报告周期。默认以用户所指本周六为结束日，包含当天向前共 14 天，即结束日减 13 天至结束日；跨月按实际日期，不从月初起算。若用户指定其他周期则采用用户指定。经营看板用当前业务季度从季度开始至最新可查日，标注实际截止日，不把季度或累计值写成双周新增。
2. 看钉钉本期模板、已有草稿和用户人工修改；以最新用户版本、已确认提纲及当期指示为准。保留其他人的栏目和用户编辑，不能整份覆盖。需要参考历史格式时，可查看 `market_workspace/Notes/周报制作参考_good_case.md` 和已验收案例，但历史数字和旧状态不能当作本期事实；冲突时以本 Skill 和较新的用户要求为准。
3. 查当前经营看板及腾讯文档；需要数仓时在 `market_workspace/` 运行 `./oxhor status`，使用显式 release 查封存语义查询，或按当前 Snapshot 跑受控原始查询，每次使用唯一 run_id、留存证据，不直连 DuckDB。看板及查询截止日和数据缺口要实际核对。留学官方记分卡覆盖的指标以记分卡为准。
4. 先汇总并校验数字，再写正文。用户已确认结构时直接写，不强制每期先征求大纲；仅在周期、业务归属等无法判断且影响结论时询问，同时继续能做的工作。

## 报告结构

保持钉钉现有栏目，通常包括业绩分析、近两周投放素材分析、下周素材计划、两周内核心关注点。数据展示以清晰表格为主；可用 HTML 排版并渲染为高清 PNG 插入，分析使用图片外可编辑文字。表格过长时按条线拆页，保留逐条素材，不强行把系列或标签合并；留学和语培保持同等层级与视觉重视，不为凑数编造、删掉有意义素材或虚构共用。只有源表或业务确认实际共用时才标注共用，保留原归属。

### 业绩与各条线投产

- 展示当前业务季度截至最新可查日的进度、目标完成、花费、工单、现金及参考 ROI，依照看板已确认口径拆解。先给各条线整体，再给平台明细。默认分别展示留学预备、高中、大学；留学及小语种投放数据无法可靠拆分时合并展示。SEM 搜索投放独立列示、不分摊到留学或语培；非搜索平台如闲鱼单列，不归入 SEM。
- 用数据指出高成本、低回收、渠道分工和重点改进项；不要把平台现金和工单当作单条付费素材的直接归因。

### 投放素材与内容生产

- 每条线呈现平台整体、当前在投与历史素材、本期已交付素材流水。留学及小语种在投与历史素材合并一个板块，不强拆英澳、北美、欧亚的投产；条线名称按腾讯文档当前下拉实际值。按投流、自然流／官号分组，保留素材标题、ID、原始标签、交付日期、平台、状态，以及已知的浏览、花费、工单、工单成本、单素材 ROI；数据未关联显示“—”，真实零显示 0。按素材 ID 和平台匹配，不把跨平台反馈混为单平台结果。
- 本期流水只纳入本期已交付素材；待拍、待剪、待发布等明确未完成记录不算已交付。交付日期、状态或其他信息冲突/不明时，核对来源，不以 ID 编号日期或空白状态独自推定已交付；无法核实的单独标注待核对，不混入已交付统计。
- 小红书和抖音分别展示平台整体与本期新素材反馈，口径、截止日一致且新素材是整体子集时可用差额展示历史及未关联部分；差额含未关联等时明确标注，不能冒称全部是历史素材或历史产出。窗口不同、归属无法核实或缺数时不作可靠差额，分别展示并指出限制。
- 按原始素材标签及同平台、同产品的单条表现分析内容，而非仅凭标题猜标签。找出跑量、工单成本相对有优势和消耗偏高的具体版本，比较哪些角度值得延续、改造或减少；浏览数据用于自然流观察，不当作投放转化。注意样本规模、消耗和归因差异。

### 写出决策，而不是防御性说明

每条线用自然文字写“最重要的发现 → 数字或具体素材证据 → 内容及投放判断 → 下步做什么”。有足够信号时明确建议优先、保留、调整或减量；证据薄弱时也基于现有信号提出小规模测试的具体优先级与验证方式，区分事实、用户提供的业务观察和推测，不把假设写成已证实结论。用户的投放经验是业务观察，若与数据看似冲突，要区分统计口径并呈现，而不是忽略任何一方。不要写“本表展示了什么”等写作说明。

### 下周计划和核心关注点

下周素材计划采用表格，逐条线列重点产品、计划素材方向和具体版本，例如师资、课程安排、住宿、课堂环境、申请路径、备考干货等；按本期实际产品和反馈决定，不照搬旧计划。标注已排期与建议测试的区别，有依据才写日期、数量和平台。正文文字只作必要辅助。核心关注点不超过 3 项，每项写清行动与可检查的达成标准，重点围绕投放 ROI 观测、内容生产效率以及素材从交付到浏览、花费、工单、后续转化的及时登记；历史缺失数据不假装可以追溯。

## 交付与授权

依据用户请求先交正文或填写钉钉。明确授权编辑草稿时，只改新媒体对应编辑区，确认选区后操作，检查图片清晰度、文字、字段和保存状态；保持其他人内容。默认不提交、不发送、不发布；已提交日志的修改可能影响接收人，除非用户明确要求修改已提交内容，否则先给可审阅正文或草稿。未确认自动保存时如实说明并提醒保留页面。不要通过聊天工具通知他人。

文件、工具工程及验收后收尾按[市场工作区规定](../../../market_workspace/AGENTS.md#写入位置与清理)执行，显式指定任务目录，不使用默认 `outputs/` 或 `Reports/projects/`。旧脚本 `Programs/周报_20261106/` 仅供参考，含硬编码日期、数字和旧口径，不能原样作为新一期生成器。完成时说明报告周期、截止时间、实际交付状态及影响判断的重要缺口。

同窗比较使用交集与明确截止日。周期比率汇总分子与分母后再计算。重点工单定义与筛选范围放在相应图片中。
