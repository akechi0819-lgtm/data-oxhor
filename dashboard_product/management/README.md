# 原生 BI 共同业务计算

本模块提供原生Superset BI与通知复用的教育运营规则。正式界面已上线，旧静态页面、HTML打包与旧发布/激活/兼容日更入口已删除，不保留恢复开关。服务器持有历史数仓基线，并由受限raw worker完成新输入合并、双Snapshot、quality及聚合计算；不再将服务器描述为只能装载成品表。运行合同见 [部署说明](../DEPLOYMENT.md)、[raw合同](../../docs/server-raw-pipeline-contract.md)。

## 代码与数据流

`calculation.calculate` 是业务编排入口，读取明确工作区、run_id、双Snapshot与日期，经Data Platform受控查询取得事实，复用同一组归属、聚合、期间、目标、人员与通知规则。`shadow_bi.library` 将模型封存为typed业务库/39表，服务器固定publisher经P4复验激活至Superset。通知从固定正式release经 `release_notifications` 构建同批包，`shared_delivery` 负责渲染和逐消息去重，不再从旧页面批次指针触发。

`online_team/build.py` 当前只有共享期间、指标、归属与查询helpers，没有旧页面生成器；`refresh.py` 的归属及历史对照算法仍被共同计算直接调用，不是旧站恢复入口。`validation.py` 校验聚合模型身份及隐私字段边界，不生成HTML。删除展示代码不改变业务公式。

## 现行口径

- 语培工单使用已验收团队/业务组范围，并按被动／主动／全部筛选；全部为主动加被动，不把未分类猜入。留学从独立Snapshot读取，不混入语培。
- 语培经营人头：在筛选范围内按学员编号＋班级编码汇总报入现金，金额绝对值达到1500元且报名人次为正，再按学员编号去重。期间、部门各自重算，不相加子组或月份去重数。个人业绩与人员产能沿各自独立资格，不随经营范围切换。
- 个人工单支持删除／回收与死单两个独立状态范围，现金、人头、目标与人员在职资格不随工单开关改变。通知使用确认的固定资格，页面筛选不改通知合同。
- 个人分配使用共享 `activity_co_creation_weights` 与当前花名册；本业务主办与跨业务接收分别按确认规则计算，不把已明确主办成果无差别均分。人员归属、绩效月、共创及跨业务标记以 `workspace_modeling/operations/` 为准。
- 留学资源按分单日期与资源ID；签约与小语种实缴按各自确认日期/金额/本行归属；国际市场、SSC、缺覆盖、无同比和跨系统客户不自动合并的边界保持。官方记分卡覆盖范围优先，不被数仓或历史对账覆盖，也不自动回写目标。
- 广告费用仅消费用户提供的原表及 `Input/AdvertisingCosts/sources.json` 明确相对路径/hash。ROI与单条工单成本按费用共同覆盖窗口；缺费用为空，不补0、不将月度累计差额分摊到每天。见 [费用说明](../../docs/dashboard-advertising-costs.md)。

## 完整性与证据

最大记录日不等于上游完整业务日。raw本地新门禁验证受保护来源证明，区分最大记录日与经验证昨日；完整零业务日不补造事实。证明贯穿计算、封口、候选复用与发布末次复核，缺失/变化就停止。该门禁上一轮只合入本地，未由此次清理部署服务器。见 [完整性合同](../../docs/server-source-completion-candidate.md)。

共同计算在工作区Output保存受控查询回执、费用/人员/来源诊断及绑定身份；封存业务库保留明确输入、规则与表hash。原始输入只读，不直连客户DuckDB、不从目录时间或latest猜当前状态。历史V14对账仅是方法核对，不覆盖当前事实。
