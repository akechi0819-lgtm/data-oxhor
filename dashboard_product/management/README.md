# P2 管理融合看板（隔离施工）

这是独立的本地预览模块，尚未接入正式发布或钉钉。沿用静态HTML，不新增数据库、BI服务或网页后端。正式线上融合页仍由 `online_team` 负责。

## 构建

```bash
.venv/bin/python -m dashboard_product.management.build \
  --workspace customers/bi_operations \
  --snapshot-id <workspace.json中当前明确Snapshot> \
  --run-id run_p2_<唯一批次> \
  --as-of-date <上海日期>
```

产物位于工作区 `Output/DashboardManagement/<run_id>/`：

- `site/`：仅展示用数据与静态网页，可单独提供本地HTTP服务。
- `index.html`、`university.html`、`prep_high.html`、`online.html`：自包含静态页，沿用统一导航。
- `shared_result.json`：同批汇总与查询身份，供下一阶段推送消费。
- `details.json`：逐笔事实与贡献人，只留本地，不通过site目录提供。
- `reconciliation.json` / `.md`：同Snapshot现有V14复算对账与差异。
- `_query/`：Data Platform受控只读查询回执。

输出目录严格限制在工作区Output；重复目录必须与Snapshot、批次、日期及SQL查询参数匹配。所有日期以工单/现金共同截止日为上限，并不晚于as-of前一天。

## 规则维护入口

- 语培人员与原月度目标：`workspace_modeling/operations/people.json`。
- 大学留学团队八人及原月度目标：`dashboard_product/config/offline_market_people.json`。认人名单由配置生成，不再在P2 SQL中硬编码。
- 语培部门目标：`dashboard_product/config/project_targets.json`。
- 大学留学部门目标：`dashboard_product/config/offline_market_targets.json`。
- 线上留学目标及SSC排除：`dashboard_product/online_team/config/study_abroad_targets.json`及已确认渠道规则。
- 空团队顾问业务线映射：`dashboard_product/online_team/config/confirmed_team_mapping.json`。

P2不修改这些现有配置和原始输入；当前负责人名单用于已确认管理视图，不推断历史组织调动。

## 口径

团队按自然月，个人按26日至次月25日。个人10月在9月26日开始，不因10月团队自然月未开始而隐藏已发生实际。大学市场主业务线目标取原表，另一业务线为该月目标的10%四舍五入；未配目标保持未配置。

个人考核与产能独立：跨部门语培只计产能。大学留学部门仅按已确认八人贡献归属，不按学生学校/年级，也不因大学语培人员提供留学线索而自动归入该部门。

语培人头是在被动、新生、正向报入现金范围内按学员编号去重，不设1500门槛；部门/期间各自去重，不能相加个人或月份去重数。个人共同归属按1/N分摊，同一人员同一学员重复出现取最大权重。

活动按可用历史截至共同截止日累计，关键词子串搜索；回收倍数=已接入现金/输入投入，非利润。数据覆盖不等长时必须标注，不能假称活动全生命周期。留学现金及人头未接入，混合活动现金只代表已接入语培部分。

## 验证

```bash
.venv/bin/python -m unittest discover -s dashboard_product/management/tests -v
```

运行完成后还需真实构建、同窗对账以及桌面/窄屏交互检查。P2验收不等于P3推送已接入或公网已替换。


## 独立页面与原功能恢复

`site/index.html` 为总看板、产能与活动入口；`site/prep_high.html` 为留学预备＋高中独立工作表式看板，`site/university.html` 为大学双业务线独立看板。每页只加载自身所需的展示数据；人员月份独立于部门年/季/月筛选。恢复的业务组、渠道与学校拆解由 `breakdowns.py` 从同批事实计算，前端仅呈现、排序和筛选，不重算业务归属、目标、人头或同比。

`packages/` 和输出根的独立单HTML用于打包核验；不将private details或对账作为网页展示模块。38项相关测试的执行入口为 `python -m unittest dashboard_product.tests.test_management dashboard_product.tests.test_online_team`。


## 已确认的新版交互（2026-09-30）

- 统一六项导航：市场总览、线上平台、留学预备＋高中、大学、人员产能、市场活动。线上页由已验收 `online_team` 模块在同一Snapshot下独立构建并嵌入导航，不借整合改口径。
- 渠道、学校按语培/留学平铺两表；工单和现金均保留当期/同期/同比及占比。可切换“渠道×业务组”“学校×年级”直接看明细，不逐行折叠。
- 学校默认按工单降序显示前30所，支持现金排序和其余学校展开；排名仅改变展示，不改变指标分母。
- 留学预备＋高中三选项多选预计算7种组合。同窗指标、去重人头和占比从所选事实重新汇总；单选青少或初中不拆原留学预备整体目标。人员按所属组筛选，个人绩效核算范围不变。
- 留学预备/高中个人留学工单实际正常显示正数或0，目标不下达、目标完成率不计算；部门留学汇总仍按此前确认不纳入。此条覆盖早期“个人也不显示留学完成”的处理。
- 总看板独立“年级表现”，按整体年级汇总，与学校前30所无关。用户确认的七/八/九年级与初一/二/三、小/中/大班与对应幼儿园年级合并显示；国外年级、研究生、博士不猜测换算。原始字段不改写。
- 产能表平铺各去向当期贡献，总工单/现金/人头附同窗比较。团队筛选控制人数，选人只切换六维雷达及均值表。六维沿用语培贡献范围，留学现金未接入不混入转化率；均值及相对均值在后台生成。
- 本地页面按需加载多选数据；自包含HTML内嵌组合结果以便静态托管。前端校验Snapshot、run_id和生成时间，拒绝混用重建前后的筛选数据。

## 人员归属边界（2026-09-30复核）

个人现金和工单均只计本人所属部门；跨部门贡献只进入产能。校代“市场人员”兜底面向全部线下花名册，不限大学。明确姓名与`备注：`粘连时先截断备注字段，再由共享团队重映射函数精确核对花名册；不扩大主被动、渠道或大学留学八人边界。取证结果见施工计划第16节。构建来源哈希同时记录共享人员规则与团队重映射源码。

个人贡献页可选择绩效月或自然月，默认绩效月。原有个人字段保存绩效窗，`person_calendar`保存自然窗的人员结果、起止日期和时间进度，预备高中7种组合分别按人员所属组筛选两套结果。月度目标保持同一已配置目标；同比、人头去重和实际完成均在对应日期窗口计算，前端不自行累计。
