## 构建

```bash
.venv/bin/python -m dashboard_product.management.build \
  --workspace customers/bi_operations \
  --snapshot-id <workspace.json中当前明确Snapshot> \
  --study-abroad-snapshot-id <StudyAbroad/current.json中当前明确Snapshot> \
  --run-id run_management_<唯一批次> \
  --as-of-date <上海日期>
```

产物位于工作区 `Output/DashboardManagement/<run_id>/`：

- `site/`：仅展示用数据与静态网页，可单独提供本地HTTP服务。
- `index.html`、`university.html`、`prep_high.html`、`online.html`：自包含静态页，沿用统一导航。
- `shared_result.json`：同批汇总、查询身份及引用哈希，供共同结果预览、发布组包和发送适配消费。
- `notifications.json` / `online_shared_result.json`：本批推送与线上页投影，仅本地保存；不公开整份JSON。
- `details.json`：逐笔事实与贡献人，只留本地，不通过site目录提供。
- `reconciliation.json` / `.md`：同Snapshot现有V14复算对账与差异。
- `_query/`：Data Platform受控只读查询回执。

输出目录严格限制在工作区Output；重复目录必须与Snapshot、批次、日期及SQL查询参数匹配。BI语培使用工单／现金共同截止日；留学使用独立来源截止日，两者均不晚于as-of前一天。共同批次分别记录两份Snapshot身份与实际覆盖，留学未覆盖月份不补0或同比。

本业务合计为 `self + received`，完成率为本业务合计/目标，自创率为 `self / 本业务合计`，自创合计为 `self + output`；工单与现金分别计算。缺目标显示“未配置”；目标为0时完成率不可用，本业务合计为0时自创率不可用。缺留学月份不得写成0。没有流转登记不能确认原资源的双分标签，但已有真实跨业务源行的个人份额仍按接收市场匹配规则计算；真实字段冲突才列待核。模块为 `personnel_contribution.py`，接入现有build。私有贡献与冲突明细留在 `details.json.personnel_contribution`，不上传网页；`public.capacity`只含人员月度汇总和待核摘要。源文件及代码哈希纳入批次 `source_hashes`。 页面不常驻显示数据覆盖、流转范围、现金来源、历史或品类口径解释；这些依据保留在私有明细与维护文档，界面保留顶部更新时间、筛选、数值和必要的未提供／未接入状态。
