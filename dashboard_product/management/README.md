## 构建

```bash
.venv/bin/python -m dashboard_product.management.build \
  --workspace customers/bi_operations \
  --snapshot-id <workspace.json中当前明确Snapshot> \
  --study-abroad-snapshot-id <StudyAbroad/current.json中当前明确Snapshot> \
  --run-id run_management_<唯一批次> \
  --as-of-date <上海日期>
```

产物位于工作区 `Output/DashboardManagement/<run_id>/`：

- `site/`：仅展示用数据与静态网页，可单独提供本地HTTP服务。
- `index.html`、`university.html`、`prep_high.html`、`online.html`：自包含静态页，沿用统一导航。
- `shared_result.json`：同批汇总、查询身份及引用哈希，供共同结果预览、发布组包和发送适配消费。
- `notifications.json` / `online_shared_result.json`：本批推送与线上页投影，仅本地保存；不公开整份JSON。
- `details.json`：逐笔事实与贡献人，只留本地，不通过site目录提供。
- `reconciliation.json` / `.md`：同Snapshot现有V14复算对账与差异。
- `_query/`：Data Platform受控只读查询回执。

输出目录严格限制在工作区Output；重复目录必须与Snapshot、批次、日期及SQL查询参数匹配。BI语培使用工单／现金共同截止日；留学使用独立来源截止日，两者均不晚于as-of前一天。共同批次分别记录两份Snapshot身份与实际覆盖，留学未覆盖月份不补0或同比。

## 口径

语培市场总盘从 `market_orders.sql` 的逐ID被动工单投影计算，先按工单ID保留源首行，再排除源团队明确为留学，以及源团队为空且跟进顾问在 `confirmed_team_mapping.json` 已确认归留学的工单；当前与上年同窗使用同一排除规则。非空团队不按顾问改写，留学预备及名单外顾问保留原规则。按原业务组映射保留真实暂无法拆分，纳入删除／回收并按ID去重，匹配原市场目标；没有已确认留学归属的传统被动TMK工单仍计入总盘和“业务组暂无法拆分”。留学专项按独立来源人工归属拆分；SSC、国际市场及待确认归属计留学总盘，不进入线上／线下留学团队或语培总盘。界面只单列SSC，国际市场直接包含在总完成中；私有核对数据仍保留各归属项。语培市场完成不能包含已确认留学工单；业务组不明本身不是留学排除依据。总盘顶部标为“市场总盘”，语培／留学及部门的团队完成均包含删除／回收；个人看板工单按状态开关筛选，人员贡献产能按本页来源与资格规则计算，业务线范围有交叉时不与总盘相加。全年从2026-06-01起，第二季度从2026-09-01起，上界截至当前数据截止日，同期采用上年同窗，不能改用自然年／自然季度。历史截图须用同Snapshot、同窗并核对主被动、工单状态、去重及业务组映射，不按截图回填。

9月历史表仅作对账，不覆盖当前人员页计算。其“总留学资源／总语培资源”与当前“工单”做逐人算术比较时保留来源字段名称；月度绩效、激活归属、回收／顾问认领／对公排除和数据提供方现金归属等原表备注，作为差异线索，不能自动改变已确认的自然月、市场资源归属、两个状态开关、小语种纳入留学及接收分摊规则。金额可以先合并两业务确认分类差异，再分别回查，不能将算术差额直接判为漏单。

留学来源已覆盖2026年6月至本次10月捕获范围：`study_abroad_facts.py`通过Data Platform读取独立仓，使用确认渠道口径和必要BI年级维度；资源、现金及分域人头进入总盘、团队、个人、渠道、活动和通知的共同计算。部门工单含删除／回收／死单；个人按状态开关，现金不随关联工单状态扣除。国际市场在主看板仅计总完成，SSC界面单列，均不进入主看板个人或各分团队；人员产能单独将国际市场识别为语培向留学的真实跨业务贡献。

资源按分单日期和资源ID，同ID跨日期保留最新分单日，同日冲突拒绝；六月CRM缺业务ID时保留技术记录键，不伪造资源ID。金额按留学签约金额／归档日期及小语种实缴金额／业务日期；用户确认6、7月历史小语种“签约金额”为实收。现金归属以签约／实缴来源本行归属为权威，不用资源页覆盖。客户ID／学员编号优先，缺编号按用户确认暂用姓名同域去重；跨留学／小语种仍不拼唯一总人头。七月空个人归属只按已确认的同资源ID、分单日期、团队一致依据引用腾讯人工归属补齐，六月未标色不计市场。

逐笔历史已经标准化，后续更新受控读取已清洗Snapshot，只替换明确月份。来源确已接入但当月无记录可显示0；未覆盖历史、缺物理来源或真实缺金额不能冒充0。两条八月空金额续签保留NULL／待补，不计现金完成；留学不做同比。来源、标准历史续用、临时姓名身份及来源哈希校验见 [腾讯来源说明](../../docs/tencent-docs-study-source.md)。

跨业务工单直接按源字段识别：BI工单一级渠道精确为“双分”表示留学向语培输出；腾讯标准行的归属组为“国际市场”或`segment_id=international_market`表示语培向留学输出，留学与小语种按来源咨询类型分域。人员所属业务与团队仍按现有有效名单映射；源标记不依赖旧流转表的登记、覆盖月份或接入状态。个人半份输出／接收必须已有真实对方业务工单或现金源行；例如同场10条语培、只有3条实际留学资源，不能给其余7条生成留学数量。

对已有的真实对方业务源行，活动能命中在职的对方市场时，线下创造者记0.5额外输出、对方记0.5额外接收；未命中接收市场（如活动名空白、校代渠道无对方市场名）属于独立贡献，全部记产出者额外输出1，不另造接收人。主办多人时线下输出份额均分，接收侧多人也按当前有效共创权重分配；虚拟人不分走线下创造者的对方业务输出份额。本业务共创仍按线下在职均分、虚拟人独立全额处理。无源标记的真实来源继续沿用既定活动共创与跨业务分摊规则，不把活动名字当作另一条业务源记录。反向业务与现金采用相同分配逻辑；BI现金通过实际工单关联源标记，腾讯现金通过实际资源ID关联标记，但签约／实缴本行人工归属仍为权威，不由资源行覆盖。

人工市场资源归属人必须非空；活动的主办/接收名单与人工归属人完全不相符时，不用陌活动覆盖该人工归属。原始数据提供方文字、顾问姓名不能用来补市场接收人。已确认实例：师顺盈9月5条留学/小语种输出中，195778039、195868390按活动中的邓睿各拆0.5输出与0.5接收；校代196111109及无活动名的197539518、197454648均独立输出1，合计师输出4、邓接收1。真实字段冲突继续待核。

本轮源标记核对及改造使用`2026-10-12`完整重拉BI工单快照与当天腾讯留学快照。旧流转表只保留历史追溯，不再作为当前计数、姓名覆盖或缺失门禁；原92条待核Excel亦不作为活跃排除清单。未签约是正常业务进度，先统计真实工单贡献，实际金额产生并关联后再计现金贡献，不凭标记补造签约金额。

本业务合计为 `self + received`，完成率为本业务合计/目标，自创率为 `self / 本业务合计`，自创合计为 `self + output`；工单与现金分别计算。缺目标显示“未配置”；目标为0时完成率不可用，本业务合计为0时自创率不可用。已接入的明确刷新月份无记录时按0；未覆盖历史月份不得伪造0。真实字段冲突才列待核，源标记及分配依据进入私有流水。模块为 `personnel_contribution.py`，接入现有build。私有贡献与冲突明细留在 `details.json.personnel_contribution`，不上传网页；`public.capacity`只含人员月度汇总和待核摘要。源文件及代码哈希纳入批次 `source_hashes`。页面不常驻显示数据覆盖、现金来源、历史或品类口径解释；这些依据保留在私有明细与维护文档，界面保留顶部更新时间、筛选、数值和必要的未提供／未接入状态。

来源连通性分别由BI日期覆盖和留学标准Snapshot决定，不再受旧流转表约束。另一业务缺少源行时，不凭双分标记生成工单或金额。个人流水保留源值、源标记与分配权重，份额计算不逐笔提前舍入，金额在汇总及展示时保留两位小数。四种工单状态视图与现有默认值保持原样；对比排除死单／删除／回收时使用`00`视图，现金不随工单状态筛选而扣除。

语培人头是在被动、新生、正向报入现金范围内按学员编号去重，不设1500门槛；部门/期间各自去重，不能相加个人或月份去重数。个人分配使用当前有效共创权重；人头仍按原资格与学员去重，同一人员同一学员重复出现取最大有效份额，不把所有共创人员一律按 1/N 分配。

活动按可用历史截至共同截止日累计，关键词子串搜索；回收倍数=已接入现金/输入投入，非利润。数据覆盖不等长时必须标注，不能假称活动全生命周期。活动现金包含已接入语培与留学／小语种的实际金额，来源覆盖不同则标注范围；客户人数按语培、留学、小语种分别去重，不把跨系统人数相加冒充唯一人头。
