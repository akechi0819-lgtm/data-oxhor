# 已知边界与后续事项

更新时间：2026-09-05

## 已解决

旧版本中大量现金因工单 ID 无法匹配而无法分配团队。当前 `dashboard_actuals/v6` 已按确认顺序完成兜底归属：虚拟人→线上→TMK→校代→默认线上平台。业务组现金仍由现金表团队独立决定，工单匹配不会改变业务组总额。

## 需要区分的两个指标

- `is_work_order_matched=false`：现金工单 ID 没有在同业务组被工单表精确关联；该记录仍会按兜底规则分配团队。
- `business_group=暂无法匹配`：现金表团队不在已确认的业务组映射中；这是业务组映射缺口，与工单关联状态无关。

逐笔底稿 `attributed_passive_reported_cash/v1` 保留上述两个状态，后续对账应分别汇总，不能将“团队已分配”表述为“工单已匹配”。

## 当前待办

- `push` 子命令尚未实现，仅返回 `not_started`。
- 若后续快照重新出现业务组映射缺口，需由业务方确认 Bridge 映射后再纳入看板；当前正式产物不展示空的 `暂无法匹配` 团队入口。
- 大学 FY26 Q1 与线上看板差异 `6,979.90` 元、留学预备 FY27 差异约 `24,400` 元，业务方已确认可接受；如需消除差异，应另行取得线上看板的完整过滤/取整规则。
