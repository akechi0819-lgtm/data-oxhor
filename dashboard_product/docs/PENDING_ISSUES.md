# 已知边界与后续事项

更新时间：2026-09-05

## 已解决

旧版本中大量现金因工单 ID 无法匹配而无法分配团队。当前 `dashboard_actuals/v6` 已按确认顺序完成兜底归属：工单匹配→虚拟人→线上→TMK→校代→默认线上平台；未关联时渠道为 `暂无归属`。

## 需要区分的两个指标

- `is_work_order_matched=false`：现金工单 ID 没有被工单表精确关联；该记录仍会按兜底规则分配团队，渠道显示为 `暂无归属`。
- 未映射业务组记录不进入正式看板汇总；若重新出现，需先完成 Bridge 对齐。

逐笔底稿 `attributed_passive_reported_cash/v1` 保留上述两个状态，后续对账应分别汇总，不能将“团队已分配”表述为“工单已匹配”。

## 当前待办

- `push` 子命令尚未实现，仅返回 `not_started`。
- 若后续快照重新出现业务组映射缺口，需由业务方确认 Bridge 映射后再纳入看板。
- 正式 Bridge 的现金业务组 Override 仍需与当前 `dashboard_actuals/v6` 的“工单业务组优先、未关联回退现金团队”行为完成业务确认；本次未直接修改已确认 Bridge。
- 大学 FY26 Q1 与线上看板差异 `6,979.90` 元、留学预备 FY27 差异约 `24,400` 元，业务方已确认可接受；如需消除差异，应另行取得线上看板的完整过滤/取整规则。
